## G1-01：补齐国内 Provider 配置层

**优先级：P1**
**依赖：无**
**文件：`config.go` + `provider_factory.go`**

### 背景

当前 `DEFAULT_SETTINGS` 和 factory 函数覆盖 7 家（openai/anthropic/ollama/deepseek/qwen/glm/kimi）。
需补齐国内常用 Provider，让用户只需改配置文件即可接入新模型。

### MiMo API 关键信息（来自官方文档）

| 项目 | 值 |
|------|-----|
| 开放平台 | https://platform.xiaomimimo.com/ |
| 文档 | https://mimo.mi.com/docs/zh-CN/api/guidance/rate-limit |
| OpenAI 兼容 URL | `https://api.xiaomimimo.com/v1` |
| Anthropic 兼容 URL | `https://api.xiaomimimo.com/anthropic` |
| Token Plan URL | `https://token-plan-cn.xiaomimimo.com/v1` |
| 认证 Header | `api-key: sk-xxxxx` 或 `Authorization: Bearer sk-xxxxx` |
| 模型列表 | `mimo-v2.5-pro`, `mimo-v2.5`, `mimo-v2-flash`, `mimo-v2-pro`, `mimo-v2-omni` |
| 思考模式 | `thinking.type` = `"enabled"`/`"disabled"`（非标准 OpenAI 参数，需 extra_body） |
| 推理字段 | `reasoning_content`（**非** `reasoning`，这是与 DeepSeek/OpenAI 的关键差异） |
| RPM | 100 |
| TPM | 10M（文本模型） |
| 系统提示词要求 | 建议使用 "You are MiMo, an AI assistant developed by Xiaomi. Today's date: {date} {week}." |

## G1-02：MiMo `reasoning_content` 字段适配

**优先级：P1**
**依赖：G1-01**
**文件：`openai.go`**

### 背景

MiMo 使用 `reasoning_content` 作为思考内容的字段名（**非标准 OpenAI 的 `reasoning`**）。

当前 `openai.go` 的 `openAIChunk.Delta` 只解析 `reasoning` 字段：


## G1-04：`<thinking>` tag 归一化

**优先级：P2**
**依赖：无**
**文件：`openai.go`**

### 背景

部分模型（DeepSeek-R1/V4 的前端、某些 proxy）会将推理内容包在 `<think>` 标签中返回：

```
<think>
让我逐步分析这个问题...
</think>

最终答案
```

当前 InferGlow 的推理处理假设 `reasoning` 和 `content` 在**不同的** delta 块中。
如果模型在 `content` 中返回 `<think>` 标签包裹的推理，需要提取并归一化到 `Reasoning` 字段。

Agently 有 `LeadingThinkEventNormalizer` 做这件事，InferGlow 尚未实现。

### 具体步骤

1. **新增 `normalizeThinkingTags` 函数**：

```go
// normalizeThinkingTags 从 content 中提取 <thinking>...</thinking> 标签内的内容
// 作为单独的 Reasoning 返回，content 中去掉标签部分
func normalizeThinkingTags(content string) (reasoning string, cleanedContent string) {
    // 使用正则匹配 <thinking>...</thinking>
    // 支持多行
    re := regexp.MustCompile(`(?s)<thinking>(.*?)</thinking>`)
    matches := re.FindAllStringSubmatch(content, -1)
    if len(matches) == 0 {
        return "", content
    }
    // 取最后一个 thinking 块（通常包含完整推理）
    reasoning = matches[len(matches)-1][1]
    cleanedContent = re.ReplaceAllString(content, "")
    return strings.TrimSpace(reasoning), strings.TrimSpace(cleanedContent)
}
```

2. **在 `processOpenAILine` 和 `BroadcastResponse` 中调用**：
   - 在 SSE 流解析后，如果 `result.Content` 包含 `<think>` 标签，执行归一化
   - 将提取的 reasoning 写入 `result.Reasoning`

3. **在 non-stream 路径中也调用**：
   - 收到完整 response 后，如果 `message.Content` 包含标签，同样归一化

### 验收标准

- [ ] `normalizeThinkingTags` 正确处理嵌套标签（取最内层或最外层，文档明确）
- [ ] SSE 流中 `content` 含 `<think>` 时正确分离 reasoning
- [ ] non-stream 响应中同样处理
- [ ] 无 `<think>` 标签时原样返回 content
- [ ] 测试覆盖正常/边界/空/嵌套标签

## G1-05：推理内容预算控制

**优先级：P2**
**依赖：G1-02**
**文件：`model.go` + `openai.go`**

### 背景

推理内容（reasoning/thinking）可能非常长（数百 KB），当前 `strings.Builder` 无上限增长：
- `fullReasoning strings.Builder` 在 `BroadcastResponse` 中无上限
- `ModelResponse.Reasoning` 存储完整推理字符串

这导致两个风险：
1. **内存失控**：推理长度无上限，可能 OOM
2. **Token 消耗不可控**：推理可能占绝大部分 token 但用户不知道

### 具体步骤

1. **在 `RequestData` 或 `Options` 中增加推理长度预算**：

```go
type RequestData struct {
    // ... 现有字段 ...
    // MaxReasoningTokens 推理内容最大 token 数（0 = 无限制）
    MaxReasoningTokens int
}
```

2. **在 `BroadcastResponse` 中实现截断**：

```go
func (p *OpenAICompatibleProvider) BroadcastResponse(ctx context.Context, stream <-chan *StreamChunk) (<-chan *ResultEvent, error) {
    // ...
    var fullReasoning strings.Builder
    reasoningTokenCount := 0

    for {
        chunk, ok := <-stream
        if !ok {
            break
        }
        if chunk.Reasoning != "" {
            // 粗略估算：1 token ≈ 4 bytes（实际应接入 tokenizer）
            estimatedTokens := len(chunk.Reasoning) / 4
            if p.MaxReasoningTokens > 0 && reasoningTokenCount+estimatedTokens > p.MaxReasoningTokens {
                // 截断：只写入剩余空间
                remaining := p.MaxReasoningTokens - reasoningTokenCount
                if remaining > 0 {
                    fullReasoning.WriteString(chunk.Reasoning[:remaining*4])
                }
                break // 推理达到预算，停止收集
            }
            fullReasoning.WriteString(chunk.Reasoning)
            reasoningTokenCount += estimatedTokens
        }
    }
    // ...
}
```

3. **在 `ModelResponse` 中增加推理长度元数据**：

```go
type ModelResponse struct {
    Content       string
    Reasoning     string
    ReasoningTruncated bool  // 是否被截断
    // ... 现有字段 ...
}
```

### 验收标准

- [ ] `MaxReasoningTokens` 为 0 时无限制（向后兼容）
- [ ] 达到预算时正确截断并设置 `ReasoningTruncated = true`
- [ ] 截断后 `ResultEvent{Type: EventDone}` 包含 `ReasoningTruncated` 标志
- [ ] 测试：预算内/预算边界/超过预算/零预算
