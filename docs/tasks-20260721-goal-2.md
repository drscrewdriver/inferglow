## G2-01：RAG 管道

**优先级：P1**
**文件：新模块 `rag/`**

### 背景

对标 LangChain/LangGraph 成熟的 RAG 能力。InferGlow 目前零 RAG 代码。RAG 是对标 Agently 的关键差异能力之一。

### 具体步骤

#### G2-01.1：Embedding 模块

文件：`rag/embed.go`

```go

    Embed(ctx context.Context, texts []string) ([][]float64, error)
    ModelName() string

// EmbeddingProvider 从 ModelRequester 适配

    model.ModelRequester
}

// 内置：OpenAI Embeddings（复用 OpenAICompatibleProvider）

// 内置：Ollama Embeddings
func NewOllamaEmbeddings(baseURL, model string) Embedder
```

#### G2-01.2：文档切分（Splitter）

文件：`rag/splitter.go`

```go
// TextSplitter 将长文本切分为 chunk
type TextSplitter interface {
    Split(text string) []string
}

// RecursiveCharacterSplitter：按字符分隔符递归切分
```

#### G2-01.3：向量存储（Vector Store）

文件：`rag/vectorstore.go`

```go

// InMemoryVectorStore：内存实现（开发/测试用）
```

## G2-03：Azure OpenAI Provider

**优先级：P0**
**文件：`model/azure.go`**

### 背景

企业级场景常用 Azure OpenAI，与标准 OpenAI 的差异仅在于：
- 端点格式：`{resource}.openai.azure.com`
- API-Key header 名称：`api-key`（非 `Authorization`）
- API 版本参数：`api-version={api_version}`

### 具体步骤

1. 在 `config.go` 的 `DEFAULT_SETTINGS` 中新增 `"azure"` 配置项：

```go
"azure": {
    "model":       "gpt-4",
    "base_url":    "https://{resource}.openai.azure.com",
    "api_version": "2024-02-15-preview",  // 新增字段
},
```

2. 在 `provider_factory.go` 中新增 `NewAzureProviderFromConfig`。

3. 特殊处理：在 HTTP 请求中注入 `api-key` header 和 `api-version` query parameter。

4. `ProviderConfig` 新增 `APIVersion string` 字段（`model/config.go`）。

### 验收标准

- [ ] `DEFAULT_SETTINGS` 新增 `"azure"` 配置项
- [ ] `ProviderConfig` 新增 `APIVersion` 字段
- [ ] `NewAzureProviderFromConfig` Factory 函数
- [ ] HTTP 请求正确注入 `api-key` header 和 `api-version` query
- [ ] 测试：mock Azure 端点验证 header 和 query

## G2-07：Memory Plugin 系统

**优先级：P2**
**文件：`session/memory_plugin.go`**

### 背景

记忆系统是 Agent 长期运行的核心能力。当前 `session/` 仅有 `persistence.go`（持久化到文件），无记忆抽象。

### 具体步骤

#### G2-07.1：Memory 接口定义

文件：`session/memory_plugin.go`

```go
// MemoryPlugin 记忆插件接口
type MemoryPlugin interface {
    // Name 返回记忆类型名称
    Name() string
    // Save 保存记忆条目
    Save(ctx context.Context, entry MemoryEntry) error
    // Query 查询记忆（按语义/关键字/时间）
    Query(ctx context.Context, q MemoryQuery) ([]MemoryEntry, error)
    // Delete 删除记忆
    Delete(ctx context.Context, id string) error
}

// MemoryEntry 记忆条目
type MemoryEntry struct {
    ID        string
    Type      MemoryType  // short_term / long_term / episodic / semantic
    Content   string
    Metadata  map[string]any
    CreatedAt time.Time
}

// MemoryQuery 记忆查询条件
type MemoryQuery struct {
    Keywords []string
    Semantic []float64  // 语义搜索向量
    Limit    int
    Since    time.Time
}
```

#### G2-07.2：内置记忆实现

```go
// InMemoryMemoryPlugin 内存记忆（开发用）
func NewInMemoryMemoryPlugin() MemoryPlugin

// PersistentMemoryPlugin 持久化记忆（写回文件/DB）
func NewPersistentMemoryPlugin(persistence Persistence) MemoryPlugin
```

#### G2-07.3：与 Session 整合

在 `session/session.go` 中增加 MemoryPlugin 集成：
- `AddMessage()` 时自动存入记忆
- `BuildPrompt()` 时自动检索相关记忆

### 验收标准

- [ ] `MemoryPlugin` 接口定义完整
- [ ] `MemoryEntry` / `MemoryQuery` 结构体定义
- [ ] `InMemoryMemoryPlugin` 实现
- [ ] `PersistentMemoryPlugin` 实现（复用 `persistence.go`）
- [ ] 与 Session 整合（AddMessage/BuildPrompt 钩子）
- [ ] 测试覆盖

## G2-08：EventBus / EventCenter

**优先级：P3**
**文件：`orchestrator/eventbus.go`**

### 背景

当前 `orchestrator/` 仅有 `agent/` 和 `actionruntime/`，无事件中心。EventCenter 用于模块间解耦的异步事件通信。

### 具体步骤

文件：`orchestrator/eventbus.go`

```go
// EventType 事件类型
type EventType string

const (
    EventAgentRunStart      EventType = "agent.run.start"
    EventAgentRunComplete   EventType = "agent.run.complete"
    EventAgentRunError      EventType = "agent.run.error"
    EventLLMRequest         EventType = "llm.request"
    EventLLMResponse        EventType = "llm.response"
    EventLLMError           EventType = "llm.error"
    EventActionCall         EventType = "action.call"
    EventActionComplete     EventType = "action.complete"
    EventActionError        EventType = "action.error"
)

// Event 事件结构
type Event struct {
    Type      EventType
    Timestamp time.Time
    SessionID string
    RunID     string
    Payload   map[string]any
}

// EventBus 事件总线
type EventBus struct {
    mu       sync.RWMutex
    handlers map[EventType][]EventHandler
}

type EventHandler func(ctx context.Context, event *Event) error

func (eb *EventBus) Subscribe(eventType EventType, handler EventHandler)
func (eb *EventBus) Publish(ctx context.Context, event *Event) error
```

### 验收标准

- [ ] `EventType` 枚举定义完整
- [ ] `Event` 结构体定义
- [ ] `EventBus` Subscribe/Publish 线程安全
- [ ] 与 `agent.Engine.executeLoop` 整合（关键节点发布事件）
- [ ] 测试覆盖

## G2-09：TaskDAG 图编排

**优先级：P3**
**文件：新模块 `dagscheduler/`**

### 背景

对标 LangGraph 的 DAG 图编排能力。当前 InferGlow 的 `flow/` 仅支持线性序列和简单分支，无法表达有向无环图（DAG）。

### 具体步骤

#### G2-09.1：DAG 核心

文件：`dagscheduler/dag.go`

```go
// Node DAG 节点
type Node struct {
    ID        string
    Name      string
    Handler   Handler  // func(ctx, input) (output, error)
    InputExpr string   // 上游节点输出选择器，如 "node1.output"
}

// DAG 有向无环图
type DAG struct {
    Nodes map[string]*Node
    Edges []Edge  // Edge{From, To}
}

// Scheduler DAG 调度器
type Scheduler struct {
    dag    *DAG
    engine Engine  // 执行引擎
}

func (s *Scheduler) Execute(ctx context.Context, input any) (any, error)
```

#### G2-09.2：Cycle Detection

文件：`dagscheduler/validation.go`

```go
// Validate 检测循环依赖
func Validate(dag *DAG) error
```

#### G2-09.3：与 Flow 整合

在 `flow/` 中增加 DAG 执行模式（`Sequential`、`Branch`、`DAG`）。

### 验收标准

- [ ] `DAG`、`Node`、`Edge` 结构体定义
